## Коротко

Продукт не выглядит нейрослопом из-за одной большой ошибки. Он выглядит так из-за **отсутствия ограничений**: любой элемент может быть любого размера, любого цвета, с любым скруглением, и почти каждый экран считает своим долгом объяснить сам себя абзацем текста.

Замеры одной страницы («Обзор», 8788) против одной страницы реального продукта:

| Параметр | Sentinel | Grafana | Что это значит |
|---|---|---|---|
| Размеров шрифта на странице | **15** (включая 9.5px, 10.5px, 12.5px, 13.3333px, 14.5px) | 4 (из них 43 из 54 элементов — 14px) | нет шкалы, каждый размер подобран на глаз |
| Начертаний | **6** (400…900) | 3 (фактически 400 и 500) | «жирнее = важнее» вместо иерархии |
| Радиусов скругления | **9** | фактически один (6px) | элементы не выглядят одной системой |
| Разных теней | **10** | 3 | тень как украшение, а не как высота |
| Текста моноширинным шрифтом | **45%** | **0%** | ключевая причина «дурацких шрифтов» |
| Пояснительного текста в шапках | **631 слово** | 8 слов подзаголовка | интерфейс не доверяет себе |
| Реально загруженных шрифтов | **0 из 2** | Inter загружен | всё рендерится не тем, что задумано |

Ни один из этих пунктов не про вкус. Все семь измеримы и все семь чинятся.

## 0. Корень: два слоя CSS воюют друг с другом

Это надо понять до всех остальных правок, иначе они не приживутся.

В каждом шаблоне сначала идёт большой блок `<style>`, и **только после него** подключается дизайн-система:

```
templates/console/dashboard.html:232   </style><link rel="stylesheet" href="/static/design-system.css">
templates/env/dashboard.html:251       </style><link rel="stylesheet" href="/static/design-system.css">
```

CSS при равной специфичности выигрывает тот, кто ниже. Значит `design-system.css` перебивает инлайн-стили шаблона. Я сверил селекторы:

- `templates/console/dashboard.html` — 166 селекторов инлайн, **105 из них переопределены** в `design-system.css`
- `templates/env/dashboard.html` — 186 селекторов инлайн, **90 переопределены**
- `templates/env/login.html` — все 23 строки инлайн-CSS мертвы целиком (`design-system.css:709–720` переопределяет `.wrap`, `.left`, `.left .logo`, `.left .tag`, `.left ul li`, `.right button`)

Последствия, которые видно на экране:

1. **Сайдбар в шаблоне описан как фиолетово-синий градиент, а на экране он белый.**
   `console/dashboard.html:11` говорит `.side{background:linear-gradient(178deg,var(--accent-brand),var(--info),var(--info));color:var(--info)}`. Побеждает `design-system.css:236` — `background:var(--surface-1)`. То есть в исходнике живёт описание сайдбара, которого не существует уже давно.

2. **Кнопки описаны со свечением, а рендерятся плоскими.**
   `console/dashboard.html:94–96`: `box-shadow:0 2px 8px #7c3aed44` и на ховере `transform:translateY(-1px);box-shadow:0 4px 14px #7c3aed55`. Побеждает `design-system.css:391` — `box-shadow:none`. Свечение мёртвое, но лежит в файле и вводит в заблуждение.

3. **`design-system.css` сама превратилась в свалку заплаток.** Строки 709–720 — это не компоненты дизайн-системы, это точечная нейтрализация стилей страницы логина. Дизайн-система, которая чинит конкретную страницу, перестала быть дизайн-системой.

**Что делать (это правка №1, до всего остального):** удалить блоки `<style>` из шаблонов целиком, перенести в `design-system.css` только те правила, которых там ещё нет, и запретить инлайн-CSS в шаблонах. Пока это не сделано, любая правка «не работает» через раз, и следующим шагом кто-то допишет ещё один размер шрифта поверх.

Ни один из этих четырёх токенов в `design-system.css` не объявлен — я проверил. Значит страница целиком рендерится тёмными фоллбэками на светлом фоне.

## P0 — семь вещей, из-за которых это читается как нейрослоп

Порядок = порядок работ. Первые три дают 80% эффекта.

### P0.1 Шрифты, которых нет на машине

`design-system.css:86–87`:

```css
--font-sans:'Inter',-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,sans-serif;
--font-mono:'JetBrains Mono','Cascadia Code',ui-monospace,SFMono-Regular,Consolas,monospace;
```

Ни `@font-face`, ни `<link>` на шрифты нигде нет. Я проверил в браузере измерением ширины глифов:

```
Inter:          НЕ доступен  → всё рендерится в Segoe UI
JetBrains Mono: НЕ доступен  → всё падает в Cascadia Code
```

**Cascadia Code — это шрифт Windows Terminal.** У него характерная кириллица, слэш в нуле и курсив с завитками. Именно он рендерит 45% интерфейса. Вот это и есть «дурацкие шрифты» — не выбор дизайнера, а случайный фоллбэк.

Хуже того: на машине без Cascadia Code (любой чужой ноутбук, проектор в аудитории) фоллбэк уедет в Consolas, и вёрстка поедет вместе с ним, потому что метрики другие.

**Правка.** Положить `Inter` (variable woff2, ~110 КБ) в `static/fonts/` и объявить локально:

```css
@font-face{
  font-family:'Inter';
  src:url('/static/fonts/InterVariable.woff2') format('woff2-variations');
  font-weight:100 900; font-display:swap; font-style:normal;
}
```

Моноширинный **не self-host'ить** — он после правки P0.2 будет нужен на 3% текста, ради этого не стоит тащить файл. Оставить честный системный стек:

```css
--font-mono: ui-monospace,'SF Mono','Cascadia Mono',Consolas,'Liberation Mono',monospace;
```

`'Cascadia Mono'`, а не `'Cascadia Code'`: Mono — это тот же шрифт без программистских лигатур (`->`, `!=`, `>=`), которые в таблице с рисками и таймстемпами выглядят как опечатки.

### P0.2 45% интерфейса набрано моноширинным

Замер на «Обзоре»: 837 из 1863 текстовых элементов — моношириной. В `design-system.css` `var(--font-mono)` встречается **51 раз**, и вот на чём он висит:

```
.hint  .t-meta  .num  .al .ts  .al .rk  .ds-tl-time  .ds-feed-time  .brow b  .brow .bpct
.cell .tid  .wfcount .n  .wfi .meta  .sla  .kcx b  .kcsum b  .clock .val  .rc-sub
.frow .atag  .evrow .atag  .field .val  .spark-now  .ds-q-meta  .ds-cov-num
.ds-cov-legend b  .ds-table td .rk  .ds-inc-risk  .ds-covcard-n  .rule .tech
.case-inc-id  .rp-clock  .rp-tile b  .rk-n  .badge  .stpill  .vpill  .ly  .af  .side-foot
```

Из этого списка моноширинный оправдан примерно на пяти позициях. Остальное — русские слова, набранные шрифтом для кода. На экране это выглядит так: **«работает · 11м»**, **«пишет»**, **«готова»**, **«вкл»**, **«8 детектов · 4 тактики»**, **«показано 39 из 39»**, **«пароль печатается в консоли при старте»** — всё Cascadia Code.

Grafana на сопоставимой странице: **0% моноширинного.** Datadog, Sentry, Elastic — то же самое: моно только в теле лога, в редакторе запроса и в значении поля.

**Правило, которое надо записать и соблюдать:**

> Моноширинный шрифт применяется только там, где символы нужно сравнивать посимвольно или где важно выравнивание в колонку: тело лога, запрос, хэш, IP, путь к файлу, ID техники ATT&CK (`T1552.001`), сырое значение поля события.
>
> Моноширинный **не** применяется к: русским словам в любом контексте, статусам, подписям, подсказкам, названиям правил, счётчикам, процентам, относительному времени («7м», «2 с назад»).
>
> Цифры в колонках выравниваются не моноширинным шрифтом, а `font-variant-numeric: tabular-nums` — Inter это умеет.

Конкретно: из 51 использования оставить `code`, `kbd`, `pre`, `.mono`, `.cell .tid`, `.ds-ev-item code`, `.field .val`, `.console`. Остальные 43 — снять, добавив вместо них `font-variant-numeric:tabular-nums` там, где это числовая колонка.

### P0.3 «Что это. Откуда. Что делать.» — 631 слово поверх интерфейса

Это самый узнаваемый признак сгенерированного продукта, и он на **каждом** экране 8788.

`templates/console/dashboard.html`, блоки `.ctx` на строках **354, 390, 398, 418, 468, 486, 494, 507, 538, 554** — десять блоков, 631 слово.

Примеры дословно:

- **Алерты** (стр. 354, 96 слов): *«Что это. Сырой поток срабатываний детектора… Откуда. Каждое событие мира проходит четыре слоя… Risk — их слияние: логит риска складывается из СВИДЕТЕЛЬСТВ слоёв поверх общего приора… Что делать. Фильтры сверху разделяют источники…»*
- **Сущности** (стр. 486): содержит формулу в теле баннера — `−log₂P(репозиторий) − log₂P(действие) − log₂P(час) − log₂P(всплеск)`
- **Очередь триажа** (стр. 494): *«**Как в реальном SOC**: очередь по важности, статусы, SLA-таймеры»*

Почему это убивает доверие сильнее всего остального:

1. **Структура «Что это / Откуда / Что делать» — это шаблон ответа языковой модели**, а не структура интерфейсной подсказки. Её узнают мгновенно.
2. **КАПС для акцента внутри предложения** («СВИДЕТЕЛЬСТВ», «НАБЛЮДАЕМЫМ», «ИЗ АЛЕРТОВ», «ЛОЖНОЕ», «БИТАХ»). В `design-system.css` в шапке файла записано собственное правило: *«Капс — только в шапках таблиц»*. Оно нарушено в семи местах в тексте баннеров.
3. **«Как в реальном SOC»** — интерфейс объясняет пользователю, что он похож на настоящий продукт. Настоящий продукт этого не говорит никогда.
4. Баннеры съедают первые 60–100px каждого экрана — там, где должны быть данные.

**Правка.** Все десять `.ctx` удалить из вёрстки. Вместо них:

- Одна строка подзаголовка под H1, до 12 слов, обычным текстом `--text-2`.
  Пример для Алертов: *«Срабатывания детектора по одному событию, до склейки в инциденты.»* Точка. Это всё.
  Сравните с Grafana: заголовок «Alert rules», подзаголовок «Rules that determine whether an alert will fire» — 8 слов.
- Всё остальное — в иконку **ⓘ** рядом с заголовком раздела, раскрывающую поповер. Методику расчёта риска, слои L0–L2, формулу UEBA — туда.
- Формулу `−log₂P(...)` убрать из интерфейса совсем. Ей место в `ARCHITECTURE.md`.
- КАПС заменить на обычный регистр везде. Если нужно выделить — полужирный, и не чаще одного раза на абзац.

Отдельно — **фразы, которые интерфейс говорит сам о себе и которые надо убрать, а не переписать**:

| Где | Текст | Что не так |
|---|---|---|
| Диагностика | *«Счётчики выше относятся к текущей сессии — поэтому „ошибок нет“ и записи ниже не противоречат друг другу»* | интерфейс извиняется за собственную непоследовательность. Чинить надо счётчик, а не писать оговорку |
| Диагностика → Инфраструктура | *«Служебные подсистемы. В рабочей части интерфейса их не показываем»* | но они показаны — на «Обзоре», той же плашкой |
| ATT&CK Coverage | *«клик по технике — детали и связанные инциденты»* | если элемент кликабельный, это должно быть видно, а не написано |
| Сотрудники | *«Статистика у карточки: ↑ — пуши (коммиты) · MR — merge request'ы · ⚠ — подозрительные действия»* | легенда абзацем вместо подписей у самих чисел |
| Аналитика | *«в этот час была аномалия (красная рамка на клетке)»* | то же |
| Очередь триажа | *«Пометьте инцидент как FP (клавиша F) — после 3 подтверждений правило перестаёт поднимать инциденты»* | обучающий текст внутри панели с данными |

### P0.4 Декор, которого не должно быть в рабочем инструменте

**Розово-лавандовые пятна на фоне всех четырёх страниц:**


Цвета захардкожены, темы не знают. Это фон лендинга SaaS-стартапа. **Удалить все шесть.** Фон рабочей консоли — один плоский цвет.

**Двенадцать keyframes-анимаций:**

```
fadeup  vfade  sl  slidein  bslide  popin  ds  fadedel  flash  blink  pulse  hpulse
```

Что они делают на экране:
- `fadeup` / `vfade` (`.view.active{animation:fadeup .3s ease}`) — **каждое переключение вкладки проигрывает 300ms затухания со сдвигом**. Я поймал это на скриншотах: контент «Алертов» и «Инцидентов» снят полупрозрачным. При переходах между разделами это ощущается как лаг.

- `pulse` — расходящееся красное кольцо `box-shadow:0 0 0 7px #dc262688`.
- `blink` — мигающий фон строки.

**Оставить одно:** `transition:background 120ms, border-color 120ms, color 120ms` на ховер и фокус. Всё остальное удалить. Плюс уважать `prefers-reduced-motion`.

**24 подъёма на ховере** (`transform:translateY(-1px|-2px)`, `translateX(2px)`, `scale(1.03)` — в `design-system.css`, console и env). Карточка ATT&CK на ховере увеличивается на 3% и выезжает поверх соседей (`.cell:hover{transform:scale(1.03);z-index:2}`) — в матрице из 46 плотно уложенных ячеек это дёрганье. Убрать все. Ховер в плотном интерфейсе — это смена фона на `--surface-3`, и больше ничего.

**Свечения под кнопками:** `#7c3aed44` в console, `#5b5bd644` и `#dc262644` в env. Ни один из этих трёх цветов не совпадает с `--accent-brand` (#6366F1) — то есть даже свечение не от того цвета, что кнопка. Удалить.

### P0.5 Эмодзи вместо иконок

**Фавиконки — эмодзи, отрендеренные в SVG**, на всех пяти страницах:

```html
<link rel="icon" href="data:image/svg+xml,<svg …><text y='0.9em' font-size='90'>🛡</text></svg>">   <!-- 8788 -->
<link rel="icon" href="data:image/svg+xml,<svg …><text y='0.9em' font-size='90'>🌐</text></svg>">   <!-- 8787 -->
```

Во вкладке браузера это выглядит как самодельный проект. В `static/mark.svg` уже лежит нормальный знак — использовать его.

**Эмодзи в самом интерфейсе — 43 вхождения**, больше всего в `env/dashboard.html` (22): `📄 🟢 🗑 🗓 🌙 🏃 🔁 🧩 🎲 ⚖ 📁 💬 👍 ✓ ✕`, плюс `⚠ ⛔ 👤` в console и `💡 ⚠ ✔ ✘` в `i18n.js`.

Проблема не в том, что эмодзи «несерьёзные». Проблема в том, что **они рендерятся системным цветным шрифтом**: не подчиняются `currentColor`, не масштабируются с текстом, выглядят по-разному в Windows, macOS и на проекторе, и ломают вертикальный ритм строки. В сайдбаре уже используются нормальные SVG-иконки — значит набор есть. Довести до конца: заменить все 44 на SVG 16×16 с `stroke:currentColor`.

`🟢` как индикатор статуса — заменить на `<span class="dot dot--ok">` (8px круг на токене). `✓`/`✕` — на иконки check/x. `🗑` — на trash. `🗓 🌙 🏃 🔁 🧩 🎲 ⚖` в разделах конфигурации — на иконки соответствующих разделов либо убрать вовсе, заголовка достаточно.

### P0.6 Панели-заглушки: семь одинаковых графиков подряд

На «Обзоре» (8788) ниже сгиба идут подряд, в одном и том же визуальном исполнении «подпись → синяя полоска → число → процент»:

1. Распределение риска
2. Топ репозиториев

Семь панелей — одна форма. Это визуальный признак «данных не хватило, поэтому построим полоски из всего, что есть».

Хуже, что **сами полоски не несут информации**. «Топ репозиториев: cloud-detections — 1 — 6%». Полоска для значения 1. «Persistence — 1 — 4%» — обрубок в 20 пикселей. Полоса нужна, когда значения различаются в разы и глаз должен поймать соотношение. При значениях 1–4 из 18 это шум: **таблица из двух колонок читается быстрее и честнее.**

Плюс частности:
- Полосы синие на пяти панелях, зелёные на «Покрытии» и на «Поведенческом слое», фиолетовые в «Самых шумных правилах» на другом экране. Правила нет.
- «Поведенческий слой…» обрезан троеточием при том, что справа в панели свободно 300px.

**Правка.** Из семи оставить максимум две панели с полосами (там, где разброс значений реально большой). Остальное — компактные таблицы. Убрать проценты там, где знаменатель меньше 20: «4 из 18» информативнее, чем «22%».

## P1 — система: чем заменить

Ниже — целевые токены. Их можно вставить в `design-system.css` вместо текущих секций 1 и 3. Принцип: **меньше значений, чем сейчас, в разы.**

### Типографика

Сейчас объявлено 8 размеров, а на странице встречается 15 — значит шкалу обходят инлайном. Целевая шкала — **шесть значений и три начертания**, больше не заводить:

```css
:root{
  --font-sans:'Inter',-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,sans-serif;
  --font-mono:ui-monospace,'SF Mono','Cascadia Mono',Consolas,'Liberation Mono',monospace;

  /* шесть размеров, ничего между ними */
  --fs-xs:11px;    /* ТОЛЬКО шапки колонок таблиц, uppercase, ls .04em */
  --fs-sm:12px;    /* вторичный текст, мета, подписи под числами */
  --fs-base:13px;  /* плотные таблицы и списки */
  --fs-md:14px;    /* основной текст, навигация, кнопки, поля */
  --fs-lg:18px;    /* заголовок панели (H2) */
  --fs-xl:22px;    /* заголовок страницы (H1) */
  --fs-num:28px;   /* KPI — единственное крупное число */

  /* три начертания. 700/800/900 не существует */
  --fw-normal:400;
  --fw-medium:500;   /* акцент внутри текста, активный пункт меню */
  --fw-semibold:600; /* заголовки, KPI */

  --lh-tight:1.25;   /* заголовки и числа */
  --lh-base:1.45;    /* текст */
}
```

Почему базовый 14px, а не нынешние 13px: у кириллицы выше высота строчных, при 13px Inter она читается тяжелее латиницы того же кегля. Grafana держит 14px. Оставьте 13px для плотных таблиц, где на экране 40 строк, — это осознанный компромисс. Но навигация, кнопки, поля и текст должны быть 14px.

Что удалить из текущего файла: `--fs-h3` (13px, дублирует base), `--fs-caption` и `--fs-label` и `--fs-meta` (все три = 11px — три имени для одного значения), `--fw-display`, `--ls-display`, `--ls-h1`, `--ls-h2`.

Отдельно про `--ls-label:.02em` на 11px-подписях: разрядка на мелком кегле в кириллице разваливает слово. Убрать везде, кроме UPPERCASE-шапок таблиц, где она обязательна.

### Цвет

Сейчас в шаблонах **112 разных hex-значений** мимо токенов, и в токенах есть цвета, у которых нет работы.

**Удалить как класс:**
- `--ai:#EC4899` (розовый) и `--ai-bg`, `--ai-border` — розовый бейдж «campaign» в очереди инцидентов конкурирует за внимание с красным «critical» в той же строке. Кампания — это признак, а не уровень: показывать иконкой или текстом, не цветом.
- `--layer-ueba` / `--layer-rule` / `--layer-signature` / `--layer-ml` — четыре цвета для источника срабатывания. Источник — это факт, а не тревога, ему хватит текстовой метки. Четыре лишних цвета в палитре — это четыре повода к разнобою.
- Тему `bright`. Отличий от `light` три: полотно `#ffffff` вместо `#F8FAFC`, акцент `#4338CA` вместо `#6366F1`, семантика чуть плотнее. Все три — на уровне погрешности восприятия: я нажал переключатель темы и не увидел изменений. Переключатель, который на треть нажатий ничего не делает, читается как сломанный. **Оставить две темы: dark и light**, а если нужен режим для проектора — это отдельная кнопка «Контраст», а не третья тема в общем цикле.

**Оставить строго это:**

```css
/* поверхности — четыре, не больше */
--bg  --surface-1  --surface-2  --surface-3

/* границы — две */
--line  --line-strong

/* текст — три. Сейчас четыре, но --text-3 и --text-4 имеют
   одинаковое значение #8494AA в тёмной теме и #5A6B82 в светлой */
--text-1  --text-2  --text-3

/* семантика — четыре уровня + нейтраль. Ничего сверх */
--sev-critical  --sev-high  --sev-medium  --sev-low  --neutral

/* один акцент */
--accent  --accent-text
```

**Правило применения цвета — записать и держать:**

> Цвет в этом интерфейсе означает уровень серьёзности и ничего больше.
> Не бывает цветной полоски сверху карточки «для красоты», цветного числа «потому что оно большое», цветного бейджа «чтобы отличался».
> Если у элемента нет уровня — он серый.

Это чинит сразу пачку вещей: полоски сверху KPI-карточек на «Обзоре» (синяя, серая, серая, красная, синяя, зелёная — по какому принципу?), синее число 36345 «событий в сторе», синюю единицу «кампаний выявлено», аватарки сотрудников в восьми случайных цветах на 8787.

### Форма: радиусы, границы, тени

```css
--r:6px;        /* всё: карточки, кнопки, поля, бейджи, чипы */
--r-pill:999px; /* только пилюли статуса */
/* 50% — только аватары */

--shadow-pop:0 4px 12px rgba(0,0,0,.15);   /* поповеры, дропдауны, cmd-K */
--shadow-modal:0 16px 48px rgba(0,0,0,.25); /* модалки */
/* всё. Карточки тени не имеют — только 1px --line */
```

Сейчас на одной странице 9 радиусов (3, 4, 5, 6, 8, 10, 11, 50%, 999px) и 10 теней. Grafana: один радиус на 79 элементах из ~100, три тени на весь продукт.

Тень на карточке в плотном интерфейсе не нужна: карточек на экране 8–12, они не «парят», они лежат в сетке. Тень нужна только тому, что физически выше слоя — поповеру и модалке. Убрать `box-shadow:var(--shadow)` со всех `.card`, `.kpi`, `.inc`, `.cell`, `.pill`, `.hpill`, `.banner`, `.freshbox`, `.wrap`.

Отдельно: `env/login.html:8` — `box-shadow:0 24px 70px rgba(27,31,42,.18)`. Размытие в 70px — это тень из презентационного макета, не из интерфейса.

### Плотность и компоненты

Главная структурная ошибка обеих панелей: **каждая строка списка обёрнута в карточку** — рамка, скругление, тень, отступы 13–14px. Отсюда 50–60px на строку с двумя полями и полупустые экраны.

- «Сущности» (8788): 11 строк вида «@olga.novak … 6 алертов · 388 соб.» занимают весь экран. Это таблица из трёх колонок и 11 строк по 32px — 350px вместо 900.
- «Очередь триажа»: 10 карточек, все `critical`, все «риск 0.9x», все «1 детект · 1 тактика», все «новый», все «9м». Полная визуальная монотонность — глазу не за что зацепиться.
- «Дела»: две карточки на экран.

**Правка:** ввести один компонент `.table` и перевести на него все плоские списки — Алерты, Детекты, Сущности, Дела, Очередь, Сотрудники, Репозитории.

```
строка таблицы: высота 32px, без рамки, без скругления, без тени
разделитель:    1px --line между строками, не рамка вокруг каждой
ховер:          background --surface-3, ничего больше
выделение:      background --surface-3 + inset 2px 0 0 --accent слева
шапка колонок:  11px, uppercase, ls .04em, --text-3, sticky
```

Карточка (`.card`) остаётся только тем, чем должна быть: контейнером панели на дашборде, а не строкой списка.

**Действия в строке.** Сейчас в строке «Сотрудники» (8787) одновременно: три числа без подписей (`↑5 · MR 4 · ⚠0`), зелёная пилюля «на смене», кнопка «профиль» и голая стрелка `▾`. Четыре интерактивных на 200px. В строке очереди триажа — бейдж уровня, бейдж кампании, бейдж вердикта, бейдж статуса, таймер. Grafana в аналогичной строке: **одно меню «More ˅»**. Свести к одному первичному действию в строке плюс меню для остального.

**Вложенный скролл.** `.ds-feed{max-height:66vh;overflow:auto}` перехватывает колесо мыши: я прокручивал страницу над лентой «Живая активность», и вместо страницы прокручивалась лента. На 8787 в каждой из 8 карточек репозитория ещё и своё дерево файлов со своим скроллом. Убрать вложенные скроллы: лента показывает 8–10 записей и ссылку «Все события», дерево файлов — 5 файлов и «Ещё 9».

## Отдельно: почему интерфейс ломался молча

Самая дорогая находка этого прохода — не про дизайн.

В панели «Запись в GitLab» стояла строка

```js
pb.classList.add(pctOk >= 90 ? 'lvl-ok' : (pctOk >= 60 ? '' : 'lvl-bad'));
```

При доле успешных вызовов от 60 до 89 процентов она добавляла **пустой
класс**. Браузер бросает на этом `DOMException`, исключение вылетает из
`tick()`, и весь остаток цикла обновления не выполняется. На экране
половина значений навсегда оставалась прочерками.

В консоли при этом было пусто: цикл был обёрнут в `catch(e){}`. Таких
молчаливых обработчиков в двух консолях было **41**.

Что сделано:

- Все 41 заменены на `catch(e){uiErr('имя_функции', e)}` — ошибка идёт
  в консоль с контекстом и один раз показывается тостом. Соглашение
  зафиксировано: `catch(e)` обязан сообщить, `catch(x)` — осознанно
  проглоченная ошибка (только внутри самого репортёра).
- Тест `test_page_scripts.py` переписан: он поднимает страницу в jsdom,
  подсовывает правдоподобные ответы **всех** эндпоинтов и вызывает
  каждый цикл опроса. Пустой `{}` бесполезен — он прогоняет только ветки
  «данных нет». Дополнительно тест требует, чтобы после полного прогона
  ни одно значение не осталось прочерком.
- В `test_design_system.py` добавлены три инварианта: `classList.add`
  не может получить пустую строку, `catch(e){}` запрещён, сырых
  `snake_case`-идентификаторов в подписях быть не должно.

Тот же прогон вскрыл ещё несколько тихих поломок: обращения к
`d.items.length` и `d.counts[k]` без защиты от отсутствующего поля,
деление на ноль в ширине полосы (`NaN%` — полоса просто исчезала),
`.replace` на пустом сообщении лога, коллизия класса `.right` между
формой входа и выравниванием ячеек таблицы, `.bar2` в списке дорожек
прогресса (высота 3px обрезала содержимое), `.track` и `.tag` с двумя
разными смыслами, переключатель, стилизованный под несуществующую
разметку `.switch.on` вместо настоящего `:checked`.

## Второй заход: «текст сливается, блоки не разделены, всё квадратное»

Претензия была точной, и в основе лежала одна ошибка: плотность
доводилась до предела без обратной связи от читаемости. Строка 26px,
поле 10px, радиус 3px, тень нигде — по отдельности каждое решение
защитимо, вместе они дают решётку, в которой глазу не за что зацепиться.

Что изменено на уровне токенов:

| Токен | Было | Стало | Почему |
|---|---|---|---|
| `--r` | 3px | **6px** | 3px — визуально прямой угол; блок не опознавался как объект |
| `--r-ctl` | — | **4px** | контролу нужен свой, меньший радиус |
| `--row-h` | 26px | **30px** | 26px хватало на текст, но не на строку с двумя этажами |
| `--ctl-h` | 26px | **28px** | кнопка ниже 28px читается как элемент отладки |
| `--sec-h` | 28px | **32px** | шапка панели |
| `--gutter` | 12px | **16px** | поле между панелями |
| `--pad-x` | — | **12px** | единый горизонтальный отступ в ячейке и строке |
| `--lh-base` | 1.45 | **1.55** | межстрочный интервал в многострочном тексте |
| `--shadow-panel` | нет | **1px / 34%** | панель отделяется от полотна, а не парит |

Поверхности разведены сильнее (`--bg` #080B11, `--surface-1` #121722,
`--surface-3` #1A202C): раньше между полотном и панелью было четыре
единицы яркости на канал, границу приходилось искать. Заодно пришлось
поднять `--text-3` до #8E99A9 — на посветлевшем `--surface-4` прежний
цвет давал 4.40 против требуемых 4.5.

Где добавлен цвет — и почему именно там. Уровень серьёзности остался
точкой и цветом текста: он в каждой строке, сорок заливок подряд — это
гирлянда. А статус инцидента и вердикт аналитика на экране единичны и
являются результатом решения — они стали залитыми чипами. «FP» серым
шрифтом среди прочего серого текста не читался вообще. Матрица ATT&CK
переведена на заливку ячейки по образцу MITRE Navigator: два состояния
из трёх — «слепая зона» и «покрыта правилом» — рисовались почти
одинаковым серым, и матрица не отвечала на единственный вопрос, ради
которого её открывают.

Спарклайны на экране трендов заменены графиками с осями: заголовок с
единицей измерения, шкала слева, границы периода снизу, линия в 2px и
курсор с точным значением при наведении. «70%» рядом с безымянной
кривой — это не показатель, а украшение.

## Три бага, найденных по ходу

**Разметка, выведенная текстом.** Кнопка реплея показывала на экране
буквально `<svg class=ico viewBox=...><path d=.../></svg> Реплей атаки`:
при замене типографского `▶` на иконку строка попала в `textContent`
вместо `innerHTML`. Код корректен, опрос доходит до конца, в консоли
пусто — поймать можно только глазами.

**Печатный отчёт без единой рамки.** Инлайновый стиль отчёта по
инциденту ссылался на `var(--info)`, `var(--surface-3)` и ещё пять
переменных дизайн-системы, а отчёт открывается отдельным окном, куда
таблица стилей не подключена. Каждое такое объявление становится
невалидным на этапе вычисления: `border-bottom` уходит в начальное
значение, то есть в отсутствие рамки. Отчёт печатался голым текстом.

**Диагностика показывала чужие ошибки.** `logs/errors.log` живёт между
запусками, а страница отдавала его целиком. Пользователь видел
трейсбек `AttributeError: '_VonMisesHours' object has no attribute
'items'` — ошибку, исправленную двумя неделями раньше, — и считал её
действующей. Теперь отсечка по времени старта процесса.

## Чем это удерживается

```
python tests/test_design_system.py   границы системы: 17 проверок
python tests/test_contrast.py        WCAG AA, 90 пар в двух темах
python tests/test_page_scripts.py    страницы прогоняются с данными
python tests/run_a11y.py             структура и доступность, 32 проверки
python tests/test_i18n_rules.py      словарь синхронен с интерфейсом
python tests/test_routes.py          59 маршрутов, доступ закрыт
python run_tests.py                  весь набор целиком
```

Две проверки добавлены прямо под найденные дефекты, и обе проверены
на воспроизведение бага — сначала тест валится на исходной разметке,
потом чинится код:

- **разметка не выводится текстом** — обход текстовых узлов страницы
  после полного прогона опросов; любой `<svg`, `<div`, `<span>` внутри
  текстового узла означает `textContent` вместо `innerHTML`;
- **значения не слипаются с подписями** — ищет на границе соседних
  строчных элементов стык цифры и буквы. Контейнеры с flex/grid и
  ненулевым `gap` исключаются: там элементы разводит раскладка, и
  склейка в `textContent` ничего не значит. Список таких классов
  собирается разбором самой таблицы стилей, а не задаётся руками.

Проверка сразу нашла ещё три места помимо того, что было на скриншоте.

`test_design_system.py` падает, если в шаблоне появится блок `<style>`,
хардкод-цвет, градиент, эмодзи, `@keyframes`, подъём на ховере, размер
шрифта вне шкалы, лишний радиус, начертание тяжелее 600, моноширинный на
контейнере обычного текста или баннер «Что это. Откуда.».

Правила системы — в `static/DESIGN.md`.
