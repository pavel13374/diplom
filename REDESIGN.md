# Аудит интерфейса и план редизайна

Цель: превратить продукт из «аккуратной админки» в **рабочее место аналитика SOC**,
за которым проводят весь день. Backend, API, бизнес-логика, модели данных и
маршруты **не меняются** — работа идёт только в слое представления.

---

## 0. Реальность стека (важно для ожиданий)

Приложение — **Flask + инлайновые HTML-шаблоны с одним блоком vanilla JS** в каждом:
`console.py` (шаблон 721 строка) и `webapp.py` (867 строк). React в проекте нет.

Это не мешает задаче: Command Palette, Drawer, Toast, Skeleton, Context Menu,
виртуальные таблицы, Timeline — всё делается на нативном JS и CSS. Но реализация
будет **не на React**, а в текущем стеке. Переезд на React означал бы переписывание
шаблонов и сборку — это выходит за рамки «не трогать бэкенд» и за разумный риск
перед защитой.

## 0.1. Конфликт по теме оформления

В брифе указана **тёмная тема** (графит / тёмно-синий / slate). Ранее в работе
тёмную тему уже отвергли с конкретной причиной: «слишком тёмный, тяжело показывать»
— речь про показ с проектора.

Решение, закрывающее оба требования: **тёмная тема по умолчанию** (как в брифе,
это и есть язык SIEM/XDR) **плюс переключатель на светлую** с запоминанием выбора.
На защите — одно нажатие, если в аудитории засветка.

## 1. Аудит по страницам

### Консоль защиты (:8788) — 10 экранов

#### 1.1 Обзор
**Плюсы.** Есть KPI-строка, покрытие ATT&CK, распределение риска, AI-поле.
**Минусы и проблемы.**
- Нет строки состояния платформы: GitLab, Simulation, LLM, ML, Detection Engine, DB, API.
- Половина панелей пустует при малом потоке — экран выглядит незаполненным.
- «Пульс алертов» несёт мало смысла: 3–5 столбиков.
- Нет Live Activity, Threat Feed, очереди инцидентов, последних коммитов и MR.
- AI — голый `input` без истории, подсказок и контекста.
- **Композиция:** всё одного веса, нет фокусной точки.
- **Иерархия:** KPI и второстепенные панели визуально равны.
- **Ощущение:** статика. Не видно, что система работает прямо сейчас.

#### 1.2 Алерты
- Плоский список строк, единственный инструмент — чипы-фильтры.
- Нет поиска, сортировки, пагинации, закреплённого заголовка, группировки.
- В строке не хватает: Rule, Repository, Developer, Confidence, Affected Files.
- Нет детального просмотра справа, быстрых действий, контекстного меню.
- **UX:** нельзя работать с потоком — только читать.

#### 1.3 Инциденты
**Плюсы.** Лучшая страница по структуре: список слева, детали справа. Есть kill-chain, IOC, LLM-разбор, TP/FP.
**Минусы.**
- Детали — одна длинная лента без вкладок; всё вперемешку.
- Нет Evidence, Related Alerts, Risk Evolution, Recommended Actions, Affected Repositories отдельными сущностями.
- Kill-chain мелкий, не читается как расследование.
- Карточки в списке бедные: нет SLA, владельца, времени жизни.

#### 1.4 Очередь триажа
- Счётчики + очередь + шумные правила — логика верная.
- Нет визуальной срочности по SLA, назначения аналитика, массовых действий.
- Клавиатурный сценарий заявлен подсказкой, но не подкреплён индикацией фокуса.

#### 1.5 ATT&CK Coverage
- Матрица есть, но пассивная: нет перехода из техники в инциденты, слабый акцент на количестве детектов.

#### 1.6 Детекты
- Плоский список 22 правил со счётчиком сработок.
- Нет поиска, фильтра по severity/тактике, карточки правила, включения/выключения, связи с покрытием.

#### 1.7 Сущности
- Карточки UEBA без сравнения с базовой линией и без перехода в расследование.

#### 1.8 Red Launcher
- Кампании + очередь команд — работает.
- Нет прогресса выполнения, связи «кампания → порождённые алерты/инциденты», результата в терминах детекта.

#### 1.9 Тренды
- Четыре спарклайна. Изолированы от остальных экранов, нет выбора периода и сравнения.

#### 1.10 Диагностика
- Сырой лог. **Найдено расхождение:** KPI пишет «0 ошибок», а панель ниже показывает старые трейсбеки из файла.

### Консоль среды (:8787) — 7 экранов

- **Обзор** — три часов + 6 KPI + режим + команда. Сильная страница, но время сжато ×48 и это не объяснено визуально.
- **Конфигурация** — длинная форма без группировки по смыслу и без поиска по настройкам.
- **Журнал событий** — терминальная лента без фильтров.
- **Данные · датасет** — хорошая страница, честно показывает разметку.
- **Репозитории** — **самая убедительная страница продукта**: деревья файлов, живые MR, события. Её язык надо распространить на остальные.
- **Аналитика** — теплокарта хорошая; таймлайн аномалий беден.
- **Сотрудники** — карточки без профиля разработчика и его риск-профиля.

### Сквозные проблемы

| Область | Проблема |
|---|---|
| Навигация | Плоский список из 10 пунктов без секций; в консоли защиты нет иконок |
| Поиск | Нет глобального поиска и Command Palette |
| Таблицы | Это не таблицы, а списки `div` — нет сортировки, фиксации шапки, пагинации |
| Слои | Нет Drawer, модальных окон, поповеров — всё разворачивается инлайн |
| Состояния | Нет skeleton-загрузки: данные «прыгают» при появлении |
| Типографика | Фактически 3 уровня вместо 7 (Display → Metadata) |
| Плотность | Разная на разных экранах |
| Единство | Два приложения с разной навигацией не ощущаются одним продуктом |
| Обратная связь | Нет Toast; результат действия виден не всегда |

## 2. План редизайна

### Этап 1 — Фундамент (дизайн-система и оболочка)
- Токены: графит/slate палитра, семантика цвета (info→синий, AI→фиолетовый, ok→зелёный, warning→жёлтый, high→оранжевый, critical→красный).
- Типографическая шкала: Display / Heading / Subheading / Body / Caption / Label / Metadata.
- Сетка, отступы, радиусы, тени, состояния (hover/active/focus/disabled/loading).
- Иконки Lucide.
- Оболочка: сворачиваемый сайдбар с секциями, верхняя панель с глобальным поиском, Command Palette (Ctrl+K), статус-пилюли, уведомления.
- Переключатель тёмная/светлая с сохранением выбора.

### Этап 2 — Dashboard как центр управления SOC
Строка здоровья платформы → KPI → Live Activity → Threat Feed → Incident Queue →
Recent Commits / MR → MITRE → Top Repositories / Developers → Risk Distribution → Timeline → AI Assistant.

### Этап 3 — Поток работы аналитика
- **Алерты:** enterprise-таблица (поиск, сортировка, фильтры, фиксированная шапка, пагинация) + Drawer с деталями и быстрыми действиями.
- **Инциденты:** Investigation Workspace с вкладками Timeline / Evidence / Related / AI / MITRE / Actions.
- **Очередь триажа:** SLA-срочность, назначение, массовые действия.

### Этап 4 — Аналитические разделы
ATT&CK с drill-down, карточка правила, профиль разработчика, здоровье репозитория, Threat Hunting с сохранёнными запросами.

### Этап 5 — Консоль среды
Приведение к тому же языку; профиль разработчика; здоровье репозитория.

### Этап 6 — Живость и полировка
Skeleton, Toast, плавное появление новых событий, счётчики, индикаторы активности — без избыточной анимации.

## 3. Порядок и риск

Работа идёт этапами, после каждого — прогон `run_tests.py` и визуальная проверка
в браузере. Текущая рабочая версия не ломается: новая тема вводится через
переключатель, старое оформление остаётся доступным.
