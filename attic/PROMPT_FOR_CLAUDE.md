## 2. Дизайн UI — полный редизайн под 1920×1080

Сейчас весь HTML/CSS/JS зашит строками внутри `console.py` (~2100 строк) и `webapp.py` (~1800 строк). Целевое разрешение — **1920×1080**, интерфейс должен использовать эту площадь, а не выглядеть растянутой мобильной версией.

Архитектура фронта:

- Вынеси разметку в `templates/` (Jinja2: базовый layout + шаблон на вкладку), стили в `static/css/`, скрипты в `static/js/`. HTTP-маршруты и JSON-API не менять. Без сборщиков — чистая статика, запуск как раньше.
- Один общий `design-system.css` на обе панели: CSS-переменные для всей палитры, типографики, отступов, радиусов, теней. Никаких inline-стилей и разнобоя между 8787 и 8788.

Дизайн-система (тёмная SOC-тема, уровень коммерческого продукта — ориентиры: Grafana, Elastic Security, Datadog):

- Палитра: глубокий тёмный фон (#0d1117-диапазон), карточки на тон светлее, один акцентный цвет на панель (мир — один, защита — другой, чтобы вкладки различались мгновенно). Severity-шкала строго фиксированная: info/low/medium/high/critical — от серо-синего к красному, одинаковая везде: бейджи, графики, строки таблиц, точки на таймлайне.
- Типографика: Inter/system-ui для текста, моноширинный (JetBrains Mono) для id, хэшей, логов, фрагментов кода и секретов. Чёткая шкала размеров (12/13/14/16/20/28), табличные цифры в метриках.
- Сетка 1920×1080: фиксированный левый сайдбар навигации (иконки + подписи), верхняя строка здоровья системы (Мир/События/Детектор/Ollama/GitLab — цветные индикаторы live), контентная зона на 12-колоночной сетке. Ключевые экраны без вертикального скролла — всё самое важное above the fold.
- Компоненты: единые карточки-метрики (число + спарклайн + дельта), таблицы со сортировкой, sticky-заголовком и зеброй, бейджи severity и слоя детекта (📜 правило / 🧠 UEBA / 🤖 ML), тосты вместо alert(), скелетоны при загрузке, пустые состояния с подсказкой «что сделать, чтобы тут появились данные», модалки подтверждения деструктивных действий.
- Микродетали: плавные переходы 150–200ms, hover-состояния на всём кликабельном, фокус-обводки, кастомный скроллбар, моноширинные тултипы с сырым JSON события по клику.

Ключевые экраны — довести до состояния «скриншот в диплом»:

- **Обзор**: строка здоровья, 4–6 карточек-метрик со спарклайнами, живой пульс алертов (стрим с автообновлением), мини-ATT&CK-тепловик.
- **Алерты**: плотная таблица с цветовой полоской риска слева у каждой строки, фильтры по severity/слою/правилу как чипы, распределение риска гистограммой над таблицей, клик — выезжающая справа панель с деталями и контекстом события.
- **Инцидент**: горизонтальный kill-chain на всю ширину 1920px — узлы-шаги с цветом тактики ATT&CK и иконкой слоя, соединённые линией времени; реплей с плавным проявлением шагов; ниже — две колонки: LLM-разбор с вердиктом и «Что видела модель» (дословный контекст, моноширинно, с хэшем).
- **ATT&CK Coverage**: полноэкранная матрица-тепловик, зелёное = покрыто, красное = атаковано и пропущено, серое = не проверялось; клик по ячейке — панель с правилами и ссылкой на MITRE; кнопка экспорта в Navigator на видном месте.
- **Наука**: графики Chart.js в единой палитре — holdout (regex vs ML на невиданном формате), ROC, рост покрытия по раундам арены; каждый график с однострочным выводом под ним.
- **Очередь триажа**: kanban-подобные статусы, SLA-таймеры с цветом просрочки, горячие клавиши J/K/T/F сохранить и показать подсказкой.
- Экран логина: минималистичный, по центру, в той же теме — это первое, что видит комиссия.

## 3. Полное логирование для поиска ошибок

- Единый модуль поверх `runlog.py`: структурированные JSON-строки (ts, level, module, event + контекст: event_id, incident_id, rule_id, campaign_id — где применимо).
- Покрой все тракты: ингест (курсор, лаг), каждое решение детектора (какие правила проверялись, что сработало и почему, скоры L0/L1/ML, итоговый fusion-риск), корреляция (почему события склеились), LLM (латентность, fallback, хэш промпта), все ошибки Flask (errorhandler с трейсбеком в лог), GitLab API (ретраи, коды).
- Ротация, отдельный `logs/errors.log` для ERROR+, страница «Диагностика» в консоли: хвост лога с фильтром по уровню, счётчики, статус компонентов. `doctor.py` — до полноценной самодиагностики с ответом «что сломано и как чинить».
